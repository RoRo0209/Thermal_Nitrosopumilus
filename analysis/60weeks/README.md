# Qingdao time series: available code and restricted inputs

**The original Qingdao time-series observations are restricted and are not distributed here.** Obtain authorized inputs from the data owners. Set `THERMAL_PROJECT_ROOT` to a separate workspace containing `60weeks/`. Outputs are written into that workspace. This module cannot be run from the code checkout alone.

`Figure4_DE_time_series.R` generates the observed-temperature and ecotype-ratio traces used as the V4 Fig. 3d component. The original filename/exports retain an older figure number. It reads `out_60weeks_by_station_mgonly/60weeks_station_week_table_mgonly.csv`, with `sample`, `station`, `week_num`, `Temperature`, `HighT`, `LowT`, and the stored `ratio`, then writes `Fig4_DE_ISME_style.pdf` and `.png` in that directory. The stored ratio is used when present; the fallback has a fixed pseudocount. Thus the supplied ratio definition must be verified before matching a manuscript panel.

`60weeks.R` is retained as the historical source of the joined station/week table. Its inputs are `60week_NP_combined_relative_abundance_output.xlsx` (columns `Genome`, `group`, and station/week sample columns) and `ENV.xlsx` (`week`, `Temperature`, other environmental fields). The current raw-workbook pair was not located as a complete input set. Its additional CCF calculations use row-index lags on sparse metagenome observations; those lags must not be described as elapsed calendar weeks. They are not the canonical calendar-week inference in this release.

The available calendar-week audit scripts are separate:

1. `lag_reanalysis_20261015/reanalyse_actual_week_lags.R [--figures]` pairs observations by actual week differences, exports explicit pairs, pair counts, correlation estimates, seasonal adjustments and leave-one-week-out sensitivity. It requires `input_submitted_Data3.csv` with `sample`, `station`, `week`, `temperature`, `HighT`, `LowT`, `submitted_ratio`; the original joined table above; and `input_workbook_md5.txt` matching a workbook supplied by `THERMAL_TIME_SERIES_SOURCE_WORKBOOK`. No restricted extraction or checksum is bundled. The original source referenced a pre-V4 workbook. A V4 sheet/extraction/checksum reconciliation remains pending; the guard is intentionally retained and must not be bypassed.
2. `dense_temperature_reanalysis_20261015/analyse_dense_temperature.R` reads the generated `lag_reanalysis_20261015/source_observations.csv` and restricted `dense_temperature_reanalysis_20261015/environment_temperature.csv` (`sample_id`, `station`, `week`, `temperature`). It performs explicit temperature-week matching, common-cohort lag comparisons and adjusted sensitivity analyses, writing CSVs to its workspace directory. Input size and station-balance assertions preserve the original study design.

No row-index CCF result is substituted for exact-week matching. The available scripts do not resolve a discrepancy between an older manuscript lag interpretation and the later audit; that requires an author decision. The exact-week scripts are available evidence, not a claim that every V4 supplementary panel has been regenerated.

Dependencies: observed plot uses `readr`, `dplyr`, `ggplot2`, `patchwork`; historical preparation also `readxl`, `tidyr`, `stringr`, `mgcv`, `segmented`, `tibble`; exact-week optional figures need `ggplot2`, `patchwork`, `svglite`, `ragg`; dense-temperature analysis needs `mgcv`, `nlme`. Private R library paths were removed. Source syntax only was checked; no restricted-data execution is claimed.
